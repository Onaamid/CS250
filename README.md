## Overview

This repository contains my final project from CS-250 at Southern New Hampshire University, focused on Agile and Scrum methodologies in software development. The project involved applying Agile principles to plan, develop, and iterate on a software solution using user stories, sprint planning, and a Definition of Done framework.

## What I Learned

## Interpreting User Needs

Understanding what a user actually needs goes beyond the feature they're requesting -- it starts with understanding the goal behind the request. User stories were instrumental in keeping development focused on real value rather than assumptions. When a user story felt unclear, it was a signal to gather more information before writing a single line of code.

## My Development Approach

I work best in shorter cycles with frequent checkpoints rather than one long perfect plan. Agile habits I carry forward include maintaining a prioritized backlog, refining user stories before starting work, and using a Definition of Done so "finished" means the same thing to everyone on the team. Delivering small improvements and getting feedback early keeps quality built in rather than bolted on at the end.

## Being a Good Team Member

Good collaboration means communicating clearly, asking questions early, and making sure knowledge doesn't get trapped with one person. If I have context that helps the team, sharing it is part of the job. Respecting team standards -- including not cutting corners to move faster -- matters because shortcuts usually create more problems down the line.
